## Guidance
- Preserve commands, paths, environment variables, API fields, error codes, product names, and user-provided acceptance phrases exactly unless the task explicitly asks to rename them.
- For UI copy, docs, release notes, and translations, check this file before proposing wording.
- For internal-only names, comments, tests, or temporary debug text, do not load this file unless the user explicitly requests terminology alignment.
- If a task exposes new stable terminology, record a Knowledge Promotion decision before adding it here.
- Large auto-generated glossary dumps are not allowed; add curated terms with source and refresh condition.

## Avoid
- One-off debugging notes.
- Current task TODOs, owner fields, deadlines, or status tracking.
- Secrets, account identifiers, customer data, deployment state, or raw logs.
