Source of truth: project `AGENTS.md` for routing; individual validator scripts implement field/schema checks
Refresh when: validators, gates, templates, ship-check, reviewer policy, or release-source rules change.

> This file is an index, not a new gate. It helps choose the right deterministic validator without loading every workflow detail. Validators implement structural/schema checks for their own fields; they do not define trigger authority, accept waivers, or grant delivery approval.

## Use Rules
- Do not run every validator by default.
- Source-assurance only (`apply --include-assurance` or the starter source tree; not in default Base): `run-workflow-evals.sh`, `workflow-value-report.py`, `harness-benchmark-report.py`, `held-out-manifest-report.py`, `live-eval-profile-report.py`, `tool-surface-budget-report.py`, `agent-state-noise-report.py`, campaign / harness-evolution / skill-curator scripts. 业务任务不要把它们写成必跑命令。
- Choose validators from the scenario table below based on `Risk Tier`, `Impact Scope`, changed files, and current phase.
- For `fast path / low`, prefer direct focused verification; run a validator only when the matching risk is present.
- For `high / release`, prefer strict modes where listed.
- If a validator fails, fix the active task evidence / packet / waiver / boundary, or record a specific waiver where the owning gate permits it. A validator failure is blocking only when the owning gate marks it blocking and no complete waiver exists.
- Raw `.agents/templates/` are placeholders; template-aware validators skip them by default unless `--check-template` is explicitly used.

## Eval Taxonomy
Eval taxonomy is classification only, not a gate. It labels what a deterministic check is trying to protect so future workflow changes do not overfit to one happy-path fixture or misread a metric as delivery approval. It does not make every eval case carry all labels, does not require fast path to run the workflow validator set, and does not authorize live LLM eval.

Core classes: outcome, trajectory, tool-use, safety, provenance, state-transition.

| class | checks |
|---|---|
| outcome | final pass/fail/waived claims, acceptance status, and over-claim prevention |
| trajectory | whether the expected workflow steps, gates, reviewers, or fallbacks happened |
| tool-use | whether deterministic tools were selected, skipped, blocked, or routed correctly |
| safety | secret, external-write, destructive command, review-only, and prompt-injection boundaries |
| provenance | evidence manifests, release-source inputs, archive summaries, and run artifacts |
| state-transition | active-to-archive, review-to-implementation, and closeout transitions |

## Run Profile Map
| profile | default command | when to use | notes |
|---|---|---|---|
| focused task verification | project-specific focused test / lint / build | fast path / low and ordinary standard tasks | Do not invoke the workflow validator set just because a task ran one verification command. |
| fast workflow smoke | `.agents/scripts/verify-workflow-smoke-fast.sh` | full profile Stop hook, hook smoke markers, quick overlay health checks | Checks required hook/smoke entry points and a few cheap fixtures; it does not replace full workflow smoke after base changes. |

| workflow behavior eval | `.agents/scripts/run-workflow-evals.sh` | source-assurance / `--include-assurance` only; eval, validator, or smoke behavior changes | Not shipped in default Base. Deterministic positive/negative coverage; no live LLM eval by default. |
